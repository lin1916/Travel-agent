## 1. 本次上传包含什么

本次发布整合上次远程版本之后积累的实现，以及 2026-09-05 的实际联调修复。已有实现继续保留，不因任务报告或勾选状态缺失而重写。

### 对话和 Agent

- 旅行规划以 Conversation 为入口，而不是先填写 Trip 表单。
- 各轮聊天通过已配置的真实模型，Pi 通过 npm 依赖接入。
- `PlanningContext` 管理目的地、日期、人数、预算、偏好、假设及缺失字段。
- Agent 通过 Gateway 的白名单能力更新条件、查询高德地点和读取候选。
- 提案结构绑定 Conversation、Trip 与条件版本；正式计划必须由用户接受产生。
- 显示工具执行进度与简短理由，避免把结构化 JSON 或模型内部推理直接展示为聊天。

### 前端工作台

- 保留已有响应式页面视觉方向，整合聊天、地图探索、候选与提案界面。
- 不创建 Trip 也能搜索和保存候选地点。
- 未生成提案时不显示正式行程；接受后展示时间线与预算。
- 条件标签回填聊天输入框；支持撤销、刷新恢复和清空失败提示。
- 桌面和移动端的 fixture 浏览器场景覆盖搜索、对话、接受和恢复等操作。

### 后端和数据

- 统一 Conversation 归属校验、匿名 HttpOnly Cookie 和 CSRF 请求保护。
- 本地规划内存模式和 PostgreSQL 装配明确分开，不以缺少数据库来替换真实模型。
- 增加/整合 015 规划工作区、016 Conversation-first 迁移与相关仓储。
- PostgreSQL 提案接受以事务处理候选、计划版本与接受状态，加入版本和幂等检查。
- SSE 支持事件标识和恢复；后台具备匿名会话清理任务。

## 2. 本轮联调修复细节

| 问题 | 根因与处理 | 边界 |
| --- | --- | --- |
| 浏览器创建/修改失败 | 客户端缺少 CSRF bootstrap；补齐 Cookie/header 流程，无效校验返回 403 | 不是关闭 CSRF，也不是更换身份机制 |
| 第二轮聊天在请求模型前失败 | 恢复的 Pi assistant 历史缺少 SDK 所需 usage；补齐未知 usage 元数据供 SDK 估算 | 没有生成固定回复，继续调用真实模型 |
| 模型输出无法解析 | 明确共享结构化输出 schema 并归一化可空字段 | 无效协议仍报错，不静默用模板行程 |
| 人数丢失 | 敏感字段规则误伤数值 travelerCount/travelers | 仅保留合法的 1–6 人数值，身份对象继续脱敏 |
| 有模型回复但没提案 | 模型输出的 expiresAt 可能早于当前时间 | 由服务端设置创建后 24 小时；仍检查已存提案过期 |
| 多晚住宿导致接受失败 | 住宿被当成持续占用旅客时间 | 住宿可与活动并存；两个住宿或两个 timed 活动仍检查冲突 |
| 住宿引发虚假换乘/密度警告 | 多晚住宿参加活动排序 | 住宿不参与该排序，住宿费用仍完整计入预算 |
| 整段交通预算与全部活动冲突 | 模型把多日交通费用写成一段多日交通 | 提示模型按真实时间窗分配估算；未放开真实交通冲突校验 |

此外，修复了模块导入、仓储提供者类型、撤销 API/UI、移动端正式计划显示、过期测试数据和对话集成测试预期。发布检查中发现的 AgentRun 序列化测试按当前会话快照补齐字段，保留严格往返断言，没有删除校验来掩盖失败。

## 3. 技术实现要点

### 权限与执行边界

Web → API → Agent Runtime → Capability Gateway → 应用/领域服务 → 适配器。Agent 只发出受限工具请求；用户接受提案后，应用服务校验归属、条件版本、提案版本、计划版本、到期时间和幂等键。预算通过计划条目以整数分重新计算。

预订、TravelMandate、保险箱、审计等基础模块仍在仓库中，但当前规划内存组合不注册交易接口。不能把长期架构设计或旧模拟供应商流程理解成已实现真实预订。

### 会话与恢复

匿名身份使用 Cookie；前端仅保存会话引用和 SSE 恢复游标，不保存 API Key。内存模式可在同一 API 进程内恢复；数据库模式保存会话、候选、规划条件和计划版本。数据库完整重启/故障恢复仍需进一步验收。

### 模型与隐私

模型与高德凭据来自后端 `.env` / 环境变量，公开仓库仅放示例。高德 JS Key 本身是浏览器可见标识，需供应商域名限制；不能承诺所有地图 Key 都不出现在浏览器。脱敏后的旅行上下文会发送至配置的第三方模型服务，仍应由使用者评估该服务的数据政策。

## 5. 已知限制与下一步

1. **路线：**高德公共交通适配仍需修复城市参数/时长解析，前端默认取前两个搜索结果作为路线端点也需要改进。地点搜索成功不代表路线已可用。
2. **最后一次真实网页点击验收：**浏览器控制连接超时；最终接受流程以真实 HTTP 验证完成，未把它描述为完整网页点击通过。
3. **持久化：**内存模式 API 重启即清空；完整数据库接受、重启恢复、失败回滚和并发场景尚未全部验收。
4. **模型可靠性：**系统提示不能保证所有提案合法；缺少更完整的无效提案自动修复、整轮工具次数上限和时限治理。长行程可能耗时数分钟。
5. **预算预览：**模型生成的提案预算不等于供应商实时报价；接受时服务会重新计算条目费用。预览一致性仍需增强。
6. **推理配置：**Pi 当前 thinkingLevel 为 off，没有将环境变量里的 xhigh 自动映射为 Pi 推理等级。
7. **真实 smoke：**现有 smoke 脚本尚未在缺少提案时严格失败，不能只看进程退出码宣称全链路成功。
8. **发布准备：**没有完成本轮独立子代理审查；认证/授权、日志、限流、生产部署及供应商接入仍需正式检查。

建议下一阶段聚焦真实页面验收、地图路线、数据库恢复和模型运行边界，而不是重写已存在的界面或业务模块。
